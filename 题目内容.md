# Personal AI Agent with Tool Use, Memory & Self-Verification

## Challenge / 编程挑战

Build a fully functional CLI-based personal AI agent that demonstrates production-grade agent engineering: multi-step tool use, persistent memory across sessions, and a built-in self-verification layer that catches and recovers from tool failures.

The agent should act as a "personal productivity assistant" — it can search the web (or a simulated knowledge base), read/write notes to disk, summarize past interactions from memory, and answer multi-step questions by chaining tools. The human's job is to architect the tool design, context strategy, verification checks, and error recovery flows — not just scaffold boilerplate.

**Scenario:** The agent is given a multi-step user request such as:

> "Search for the latest best practices for LLM prompt caching, save a summary to my notes, then tell me what topics I've been researching this week based on my saved notes."

This requires: (1) a tool call to retrieve information, (2) a write tool call to persist a note, (3) a memory/retrieval tool call to summarize past notes, and (4) a final synthesis response. The candidate must design and wire up all of these tools correctly with real LLM calls.

**What the human must design (not just generate):**

- Tool schema design: what tools exist, what their inputs/outputs look like, and how the agent decides which to call
- Context engineering: how prior session memory is injected into the system prompt without blowing the context window
- Verification layer: after each tool call, a deterministic check confirms the tool actually did what it claimed (e.g., file actually written, content non-empty) before the agent proceeds
- Error recovery: if a tool call fails or the verification check fails, the agent retries or falls back gracefully rather than hallucinating success

**Deliverable:** One command (`python agent.py` or equivalent) launches the agent in CLI. The evaluator will run a multi-step query and observe the agent correctly chain tools, persist memory, and recover from at least one injected failure.

## Requirements / 需求

- Single command launches the agent CLI (e.g., `python agent.py`). The agent must handle a multi-step user query end-to-end using at least 3 distinct tools (e.g., web_search or mock_search, write_note, read_notes).
- Persistent memory across sessions: notes/summaries written in one session must be retrievable in a fresh new session without any in-memory state — backed by disk (JSON, SQLite, or flat files).
- A verification layer runs after every tool call: deterministic checks confirm the tool's side effect actually occurred (e.g., file exists and is non-empty after write_note). If verification fails, the agent retries the tool call up to 2 times before reporting failure — it must NOT proceed as if the call succeeded.
- At least one tool must be intentionally breakable via a CLI flag or environment variable (e.g., `INJECT_FAILURE=write_note python agent.py`) to demonstrate the retry/recovery flow working correctly during evaluation.
- Tool schemas are explicitly defined (as JSON Schema, TypedDict, Pydantic models, or equivalent) and passed to the LLM — the agent uses structured tool-call parsing, not freeform regex on LLM output.

## Evaluation Criteria / 评判标准

- Tool design quality: Are the tool schemas clean, minimal, and well-scoped? Does the candidate show judgment in what each tool does vs. what the LLM reasons about?
- Context engineering: How is session memory injected — does it scale gracefully as notes grow (e.g., summarization, truncation strategy) rather than naively dumping everything into the prompt?
- Verification layer correctness: Are post-tool checks deterministic and meaningful (not just 'did the LLM say it worked')? Does the retry loop actually re-invoke the tool rather than just re-prompting?
- Error recovery behavior: When INJECT_FAILURE is set, does the agent visibly retry, log the failure, and either recover or fail gracefully — never silently hallucinating a successful outcome?
- End-to-end completeness: One command, runs without errors, produces a visible multi-step agent trace the evaluator can follow. Code is readable and structured, not a single monolithic script.

## Tech Hints / 技术提示

- Python 3.10+ recommended (matches candidate's background)
- OpenAI SDK or Anthropic SDK for LLM calls with native tool/function-calling support
- Any persistence layer: JSON files, SQLite via sqlite3, or TinyDB
- LangChain optional but not required — a clean custom ReAct loop is equally valid and shows more design judgment
- Rich or simple print-based CLI trace is fine — no frontend needed
